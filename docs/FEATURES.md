# Project Features: arghamart

> Audit date: 2026-09-29. Everything below is based on files in this repo. No live database was inspected; store configuration stored in the DB (currencies, zones, rates, live payment credentials) is marked as Open questions where it cannot be read from code.

## 1. Overview (stack, versions, architecture in a short paragraph)

Rails 8.1.3.1 + Ruby 4.0.1 (`backend/.ruby-version`) API-only Spree backend (`backend/`) with Spree 5.6.1 (`spree`, `spree_core`, `spree_api`, `spree_admin`, `spree_emails`, `spree_dashboard` from `backend/Gemfile` / `backend/Gemfile.lock`), Postgres 18 + Solid Queue/Cache/Cable (jobs run in-process in Puma by default), Puma web server, Mission Control jobs dashboard, Hotwire/Turbo + Tailwind admin, and a headless Next.js 16 / React 19 storefront (`apps/storefront/`) using `@spree/sdk` against Store API v3. Custom backend work adds three Nepal-focused payment methods (eSewa, Khalti, Manual QR with screenshot-proof review), shipment “Delivered” tracking layered on the state machine, COD capture-on-delivery, a legacy-order-number admin redirect, and Manual-QR Store API proof endpoints with serializer extensions. Custom storefront work adds matching eSewa/Khalti/Manual-QR checkout forms + confirm-payment return page, order-page proof re-upload, wholesale B2B portal (gated channel), 6 locales (incl. `ne`), SEO/hreflang/sitemap, GTM analytics, and Resend webhook emails.

Key mounts/routes: `Spree::Core::Engine` at `/` (`backend/config/routes.rb`), Admin at `Spree.admin_path` (`/admin`), Store API `/api/v3/store`, Admin API `/api/v3/admin` (via `spree_api` gem), React Dashboard at `/dashboard` (via `spree_dashboard` + `backend/Dockerfile` dashboard stage), jobs at `/jobs`, health at `/up`, root `-> /admin`.

### 3.4 Payments, tax, shipping, stock (configuration)

- **Khalti gateway.** `initiate` (paisa integer, `return_url`/`website_url`/`purchase_order_*`/`customer_info`) returns `pidx`+`payment_url`; `complete` verifies via `lookup` (`Completed` + paisa match, pidx-mismatch fails). Credentials via preferences (`public_key`, masked `secret_key`, `env`). [Custom] / Enabled. Files: `backend/app/models/spree/payment_method/khalti.rb`, `backend/app/models/spree/payment_sessions/khalti.rb`, `backend/config/initializers/spree.rb`.

[Custom] / Enabled. Files: `backend/app/models/spree/payment_method/manual_qr.rb`, `backend/app/models/spree/payment_sessions/manual_qr.rb`, `backend/app/models/spree/payment_decorator.rb`, `backend/db/migrate/20260929000001_add_manual_qr_to_spree_payments.rb`.

[Custom] / Enabled. Files: `backend/db/migrate/20260916010000_disable_auto_capture_for_cash_on_delivery.rb`, `backend/app/models/spree/shipment_decorator.rb`.
- **Stripe/Adyen/PayPal.** Standard extension gateways (models + webhook/payment-session tables). [Gem/extension] / Enabled (require admin credentials + storefront keys). - **Currency/locale/tax/shipping/stock locations.** Core multi-store/market/channel/country/zone/tax/shipping/stock-location system; Manual QR is the only coded NPR gate (other currency config lives in the DB, not in code). [Spree core] (+ [Custom] NPR gate) / Enabled. ## 8. Known gaps, unfinished work, and open questions

1. **Live store data not audited.** Currency (NPR default?), locales, countries/zones, tax rates, shipping methods/rates, payment-method records + eSewa/Khalti/QR credentials, stock locations, and admin users live in Postgres, which was not queried. Verify in Admin (`/admin`) or via `pnpm spree api get stores|payment_methods|shipping_methods|tax_rates|stock_locations`.
2. **Wholesale trade pricing is a demo constant.** `WHOLESALE_MIN_QUANTITY = 10` mirrors the sample-data VolumeRule and is not read per-variant from the API (`apps/storefront/src/lib/wholesale.ts`). Confirm against `spree/core/db/sample_data/wholesale.rb` / live price lists before treating as production pricing.
3. **Meilisearch off by default.** Product search falls back to Postgres; typo-tolerant instant search needs the commented compose blocks + `MEILISEARCH_URL` + `bin/rails spree:search:reindex`.
4. **S3/R2/CDN/SMTP/Resend/Sentry/GTM all credential-gated.** Code paths exist but do nothing live until their env vars + admin settings are provided (see §7). In particular: no backups, no log retention, and no reverse-proxy/SSL beyond `RAILS_FORCE_SSL`/`RAILS_ASSUME_SSL` + Thruster are configured in-repo.
5. **Wishlist/reviews UIs not found in storefront.** Backend tables (`spree_wishlists`, `spree_wished_items`) exist but no `wishlist`/`review` components were found under `apps/storefront/src` (only email fixtures matched “review”). Either unbuilt or named differently — confirm.
6. **Multi-currency beyond NPR unclear.** Manual QR hides itself on non-NPR orders; whether the store actually prices in NPR (markets + `supported_currencies`) could not be confirmed from code alone.
7. **Phone-required checkout validation** (per git history `2377227`) was not re-verified field-by-field; spot-checked `AddressFormFields.tsx` still renders a phone input. Confirm required-ness in `PaymentSection`/address actions if it matters for eSewa/Khalti.
8. **Wholesale disabled by default.** With `SPREE_WHOLESALE_CHANNEL` unset the `/wholesale/*` routes 404 and entry points hide — expected, but easy to misread as broken.
9. **In-memory webhook idempotency.** `PROCESSED_EVENTS` Set caps at 10k and does not survive restarts or multi-instance deploys (`apps/storefront/src/lib/webhooks/handlers.ts`); fine for single-instance, lossy otherwise.

## 9. How to verify each major feature (short commands or URLs to check)

- **Stack/versions:** `grep -E "spree \(|rails \(|pg \(|puma" backend/Gemfile.lock` + `cat backend/.ruby-version`; Admin: `http://localhost:3000/admin`; Dashboard: `http://localhost:3000/dashboard`; health: `curl localhost:3000/up`.
- **Store/Admin APIs:** `pnpm spree api endpoints` and `pnpm spree api get products`; Admin API needs a scoped key: `pnpm spree api-key create --scopes write_products`.
- **eSewa/Khalti:** create methods in Admin → Settings → Payments (type Esewa/Khalti, set `product_code`/`secret_key`/`env` or `public_key`/`secret_key`/`env`); checkout with each, confirm redirect lands on `/confirm-payment/[id]` and order completes only after server verify; specs: `spree rspec spec/requests/spree/payment_sessions`.
- **Manual QR:** Admin → Settings → Payments → New ManualQr (upload QR + instructions); checkout shows QR + upload; pay → payment `pending`; Admin order → payment card shows proof → Approve (completed) / Reject with reason (void); customer order page shows `qr_status` + re-upload; specs: `spree rspec spec/requests/spree/manual_qr_proofs_spec.rb spec/requests/spree/admin/manual_qr_review_spec.rb`.
- **Delivered tracking:** Admin order → shipment → “Mark as Delivered” (only when shipped); orders table Delivered column/filter; Store API `GET /api/v3/store/orders/:id` shows `fulfillments[].delivered`; specs: `spree rspec spec/models/spree/shipment_spec.rb spec/requests/spree/store/orders_spec.rb`.
- **COD:** complete a Check/COD order → payment stays `pending`; mark shipment delivered → payment captured; spec: `spree rspec spec/requests/spree/admin/cod_payments_spec.rb`.
- **Storage:** set R2/S3 vars → upload product image → attachment URL uses bucket/CDN host; without vars, files land in `backend/storage/`.
- **Email:** dev → `http://localhost:8025` (Mailpit) or `.next/emails/*.html` (storefront dev mode); prod → set `SMTP_*` / `RESEND_API_KEY` + `EMAIL_FROM` and create Admin webhook (`order.completed`, `order.canceled`, `order.shipped`, `customer.password_reset_requested`) pointing at `/api/webhooks/spree` with `SPREE_WEBHOOK_SECRET`.
- **Search:** default works with no config; for Meilisearch: uncomment compose blocks, set `MEILISEARCH_URL`, `spree rake spree:search:reindex`.
- **Jobs:** `http://localhost:3000/jobs` (dev `spree`/`spree123` or `MISSION_CONTROL_*` in prod); recurring schedule in `backend/config/recurring.yml`.
- **Storefront pages:** home `/us/en`, PLP `/us/en/products`, PDP `/us/en/products/[slug]`, category `/us/en/c/...`, cart `/us/en/cart`, checkout `/us/en/checkout/[id]`, account `/us/en/account/*`, policies `/us/en/policies/[slug]`, wholesale `/us/en/wholesale` (needs `SPREE_WHOLESALE_CHANNEL`), sitemap `/sitemap.xml`, robots `/robots.txt`, email preview `/dev/emails`.
- **Wholesale:** set `SPREE_WHOLESALE_CHANNEL=<channel code>`, add buyer to `Wholesale` customer group in Admin to approve, verify trade pricing at qty ≥ 10 and `X-Spree-Channel` header behavior.
- **Infra:** `docker compose up -d` / `spree dev` (dev), `docker build -f backend/Dockerfile .` + Render `render.yaml` (prod backend), `apps/storefront/Dockerfile` or `vercel-build` (storefront).
